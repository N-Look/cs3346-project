- **Timestamp format:** `%d/%m/%Y %I:%M:%S %p`, for example `04/07/2017 01:53:44 PM`. This is day/month/year on a 12-hour clock with one-second resolution. Each file holds one date, and that date's weekday matches the file name:
  - Monday: date 2017-07-03 (weekday Monday), 13:55:58 to 22:01:34
  - Tuesday: date 2017-07-04 (weekday Tuesday), 13:53:44 to 22:00:30

  - Friday: date 2017-07-07 (weekday Friday), 13:59:50 to 22:02:40
- No time zone is stated. The clock times (about 13:40 to 22:10) are about 5 h later than the published local schedule of the original CICIDS2017 (about 08:40 to 17:10, Atlantic Daylight Time). This is consistent with conversion to Central European Summer Time, but that is an inference; it is not documented. Timestamps are kept timezone-naive.
- Text is parsed exactly: the parsed Timestamp formats back to the original string, and float values match Python's `float()`.
- **Dtypes:** 34 integer-valued features are stored as float32 because the cast is exactly lossless on these files. The other 42 features are kept as float64: casting them to float32 would round microsecond durations and IATs above 2^24 and would merge distinct mean/std/rate values (for example, Flow Duration would go from 867,994 to 853,382 distinct values). No feature would overflow float32. Ports are int32 and Protocol is int16. Details are in the `src/load_data.py` docstring.
